# Nova 1.0.2

A large release on both sides. The terminal surface is now multi-theme,
agent-switchable, and installable with one command; the backend gains a messaging
gateway, a closed learning loop, scheduled tasks, fine-grained agent tool policies,
and a plan agent. On top of that, the server internals were restructured: one
construction point for process handles, six store protocols behind two
implementations, a single streaming path, and a compaction package — plus four
capabilities that were configured but never actually reachable in production.

No configuration-format breaking change for existing users; new optional blocks
(`gateway`, `learning`, `terminal`) are additive. The HTTP surface and the SSE
frame format are unchanged, so existing clients keep working.

Released from tag `v1.0.2`. Version string lives in `nova/__init__.py`;
`frontend/package.json` is pinned at `0.0.0` and takes no part in the release.

## Backend restructuring

No wire change: the same endpoints, the same AI-SDK frames, the same database. The
work is about where things live and who owns them.

- **One `AppContext`.** `create_app` used to assemble seven handles onto
  `app.state` under seven names, and every reader had to know which one to reach
  for. `nova/server/context.py` now builds them in one place; routers resolve
  through `deps.context_of()`, and a settings reload swaps the chat service
  without orphaning in-flight streams (`06bd9b8`).
- **Six store protocols.** `nova/db/repository.py` declares `SessionStore`,
  `MessageStore`, `ProjectStore`, `AgentStore`, `MemoryStore` and `ScheduleStore`;
  SQLite and the in-memory double each implement them per domain under
  `nova/db/sqlite/` and `nova/db/in_memory/`. A 40-case contract suite runs the
  same expectations against both (`2252b36`, and the `refactor(db)` series).
- **`NewMessage` at the store boundary.** `add_message` took twenty positional
  parameters; it now takes one object, so a new field is added in two places
  instead of every caller (`2252b36`).
- **One streaming path.** The legacy SSE mapping (`chat_stream`,
  `_map_agent_event`, the `ServerStreamEvent` family) is gone; the console and
  `POST /api/chat` consume the same AI-SDK frames a browser does.
- **`ChatService` split.** Session, project, workspace and git routes moved to
  `SessionService`; the turn path kept its name. `feed` became 22 named event
  handlers. Turn-scoped state lives in `TurnState`, so no service reaches back
  into the agent that created it.
- **`nova/agent/compaction/`.** A 1000-line module became `messages`, `policy`,
  `summary` and `orchestrator`, with the package re-exporting the old names.
- **`mypy` at zero and gated.** 139 errors to 0 across 254 modules, and CI grew a
  fourth job so `ruff` and `mypy` cannot regress (`3d72fc1`).
- **No swallowed exceptions.** Twenty `except Exception: pass` sites either log
  or carry a comment saying why silence is correct (`6e1ad2d`).

## Fixed in the backend

Four capabilities were configured and documented but unreachable in practice:

- **Memory review never ran.** The counter lived on per-turn state while the
  agent is rebuilt for every request, so `memory_review_interval` (default 10) was
  never reached. The count now comes from the session's own history; review fires
  every N turns, and a run of three failures logs one error instead of a warning
  nobody reads (`51d09b0`, `1ad3dba`).
- **`session_search` was never registered.** `ToolsetBuilder` was built without
  the learning loop, so enabling `learning` built the index but gave the agent no
  way to query it; the tool-registry cache key also ignored the setting
  (`24454ea`).
- **fork / compact / rewind answered 409 for ten minutes.** The busy check asked
  whether a request slot existed, and a finished turn keeps its slot for
  resume/status until `TERMINAL_TTL`. Only an `active` or `detached` slot is a
  live writer (`fbad96d`).
- **`save_session` reset message counters.** Renaming, pinning or changing a
  route wrote an older copy's `message_count`/`turn_count` back over the stored
  row. Counters are the store's now (`d2ab001`).

## Upgrading

- No configuration-format breaking change; new blocks (`gateway`, `learning`,
  `terminal`) are additive. The HTTP surface and SSE frames are unchanged.
- Behaviour you may notice after upgrading, all deliberate:
  memory review now actually runs every `memory_review_interval` turns; sessions
  can be forked/compacted immediately after a reply instead of after ten minutes;
  `session_search` appears when `learning.enabled` is true; message counts in the
  session list stop resetting on rename/pin.
- `pip install -e .` users: pull and reinstall; `pip install --upgrade nova` once
  published.
- TUI: `nova tui` auto-builds the bundle on first run; `~/.nova/tui-theme.json`
  and `~/.nova/tui-theme.json` carry the theme preference.
- Gateway users: QQ adapter now requires `qq-botpy` (`pip install -e ".[gateway]"`).

## Not in this release

- `--no-modify-path` and Windows-native install are partial; the install script
  targets Git Bash/WSL on Windows.
- Pre-built TUI tarball (option B) is wired in CI but not yet published as a
  standalone download path.
- Per-agent shell policies (read-only `bash`) are not yet enforced; `plan` relies
  on the tool allowlist + prompt constraints.
