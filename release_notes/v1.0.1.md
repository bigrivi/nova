# Nova 1.0.1

The first patch after `v1.0.0`: two user-visible bug fixes and one CI cleanup. No
configuration-format change, no data migration.

Released from tag `v1.0.1`. Version string lives in `nova/__init__.py`;
`frontend/package.json` is pinned at `0.0.0` and takes no part in the release.

## Fixed

### Every TLS handshake failed in the packaged desktop app — `5e85061`

In a frozen interpreter CPython asks OpenSSL for its default CA paths, and those
paths still point at the *build machine's* Python — on macOS,
`/Library/Frameworks/Python.framework/Versions/3.12/etc/openssl/cert.pem`, a file
that does not exist on the machine running the app. The context comes back with
no trusted CAs and every HTTPS request fails with
`CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`. PyInstaller's
own `hook-certifi.py` collects `cacert.pem` as a data file and never tells OpenSSL
where it is, which is why this reproduces only in the packaged app and never in a
source checkout.

A PyInstaller runtime hook (`runtime_hook_ssl_certifi.py`) now points
`SSL_CERT_FILE` at the bundled certifi CA bundle; both aiohttp and httpx reach it
through `ssl.create_default_context()`. The other two environment variable names
cover anything that shells out to curl, and `setdefault` leaves an
operator-provided override in place. All three platform specs install the hook.

Covered by `tests/test_desktop_ssl_certifi.py`.

### The Responses provider should not send OpenRouter attribution headers — uncommitted

`openai_responses.py` unconditionally `setdefault`s
`HTTP-Referer: https://github.com/bigrivi/nova` and `X-Title: nova`, but this
provider is not OpenRouter. Measured against a gateway that fingerprints the
client (the OpenCode Zen free tier), either unexpected header is an outright
`403 FreeTierError`; removing them turns the same request into `200`.

If you do want the attribution, set it per provider in `options.headers`.

## Internal

### CI no longer runs a Windows-only nightly — `92462d5`

Releases are now published from a version tag alone
(`.github/workflows/release.yml`, `tags: ['v*']`), all three platforms together.

## Upgrading

- No configuration or data migration; replace the installed app.
- If you reach a Responses endpoint through a gateway that inspects request
  headers, 1.0.0 fails hard with a 403 and 1.0.1 does not.
- TLS is only exercised once the packaged app starts, so this fix is visible
  immediately after upgrading.

## Verification

- `pytest -q`: 2287 passed, 11 skipped
- `ruff check`: clean
- Rebuilt macOS bundle: the packaged `nova.llm.providers.openai_responses`
  contains neither the `HTTP-Referer` nor the `X-Title` literal, checked against
  the control strings `/responses`, `prompt_cache_key` and `reasoning` so a failed
  extraction could not masquerade as a clean result

## Not in this release

The region-gated OpenCode models still need `http_proxy` / `https_proxy` in the
environment of a packaged app. That is an environmental requirement, not a
release item, and is deliberately left out of the notes above.
